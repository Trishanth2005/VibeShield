Privacy Policy

Effective Date: October 2026. Academic and Local Verification Architecture.

1. Local Processing Architecture

MRU and VibeShield run entirely on your local computer. All uploaded files, chat conversations, audit logs, SQLite database records, and policy incident data remain on your local storage device. No user telemetry, analytics, or background diagnostics are collected or transmitted to external servers.

2. Web Search Operations

When you explicitly ask the agent to search the web or provide a query starting with "search", the search terms are transmitted directly to DuckDuckGo HTML search. No personal account, API key, or tracking identifier is included in these search queries.

3. URL Browsing & Document Retrieval

When you supply a web link (URL) for the agent to inspect, the local backend server process fetches the specified web page directly from the target web host. All network fetches are strictly governed by the VibeShield runtime policy engine:

  • Non-HTTP schemes (such as file:// or ftp://) are automatically blocked.
  • Private subnets (RFC 1918), loopback addresses, and cloud metadata endpoints (169.254.169.254) are rejected before socket establishment.
  • HTTP redirects are re-evaluated at every hop to prevent Server-Side Request Forgery (SSRF).

4. Model Inference

When Ollama is installed and active, artificial intelligence model inference takes place 100% locally on your computer hardware using open-source weights (such as llama3.2:3b). No prompt text or document content is sent to third-party commercial AI cloud providers. When Ollama is offline, MRU operates in deterministic basic mode without network AI dependencies.

5. File Storage & Checkpoints

Files uploaded to the workspace are stored locally in the data/workspace directory. Cryptographic SHA-256 checkpoints are kept locally in data/checkpoint to facilitate runtime self-healing and unauthorized modification rollback.
